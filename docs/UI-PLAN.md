## §1 U1 —— 对话随时可暂停

### 1.1 现状（带坐标）

| 现状 | 坐标 |
|---|---|
| 已有一个中断入口，在**顶栏** | `index.html:44` `#btn-interrupt` |
| 运行时才可用，其余时间灰着 | `app.js:961` `$('btn-interrupt').disabled = !S.running` |
| 后端 = 设一个 `threading.Event`，并把等待中的审批立刻释放为**拒绝** | `session.py` `interrupt()`（约 3780 行起） |
| 真实停止点 = 「下一次 `should_stop()` 检查」，即**每一轮授权/工具调用跑完** | `loop/agent.py:841` `if self.should_stop is not None and self.should_stop():` |
| 中断后正常收尾：发 `run.interrupted`、保留半截答案、刷新改动面板 | `session.py:3736` / `app.js:4813` |

也就是说：**能力是有的，但它是「协作式」的 —— 「在当前步骤结束后生效」这句 tooltip 是实话。**

### 1.2 真实痛点排序（这才是用户感受到的「停不下来」）

1. **跑命令时点暂停没反应**：`tools/shell.py:113` 是 `proc.wait(timeout=timeout)`，**阻塞等待**，期间完全不查中断标志。而 `timeout` 上限 600 秒 —— 一次长测试期间，暂停按钮是纯装饰。这是收益最大的一处。
2. **等模型吐 token 时点暂停没反应**：`llm/openai_compat.py:472/513` 用 `urllib` 读流，循环体内不查中断标志。虽然流式一般会立刻返回一两 token，但沉默等待（比如服务端排队）期间同样失联。
3. UI 上按钮离手指太远：它在顶栏最右端，而视线与鼠标此刻都在底部的输入框。

### 1.3 方案（三档，按性价比排序）

**P0 · composer 内加暂停键（建议必做）**
- `#btn-send` 右侧加 `#btn-stop`，同一行右端（`.composer-box` 内）。
- 二者互斥：**空闲时** 暂停键 disabled（不是 hidden —— 隐藏会让发送键在运行时横向跳动）；**运行时** 暂停键高亮可点。视觉上用 `--danger` 描边 + 🞫 图标，与「发送」的 `--accent` 明确区分。
- 调**现有** `interrupt()`，不新增后端语义。tooltip 保持诚实文案：「中断当前任务（在当前步骤结束后生效）」。
- 顶栏那个 `#btn-interrupt` 保留（命令面板/老习惯都在用它），两者共用同一个函数、同一个 `setState` 开关。

**P1 · 让暂停在两种真实等待里立刻生效（建议一并做）**
1. `tools/shell.py`：把 `proc.wait(timeout=timeout)` 换成**轮询** —— `while proc.poll() is None: sleep(0.2); if should_stop(): proc.kill(); return interrupted`。
   - 收益：长命令/长测试瞬间可停，且**复用了已有的超时 kill 路径**（不新增破坏性分支）。
   - `ToolContext` 需要带上 `should_stop`（现在只传给了 Agent，`session.py:550/3621`）——对齐同一份标志，不要各写一个。
   - 返回形态建议统一成 `status="interrupted"`，让模型知道「命令被用户停了」而不是「命令失败了」。
2. LLM 流式：在传输层暴露 `cancel()`，持有底层 response/socket 引用；UI 触发时由另一个线程关掉它 → 读循环立刻抛 `OSError` → **识别为「被用户取消」而非「网络故障」**，走 `run.interrupted` 收尾并把已生成的部分答案留下。
   - 「识别为取消」这步不能省：否则用户主动暂停会显示成红色报错（`is-err` 那条通知）。
3. 工具内部的退避等待（远端执行命令的轮询等）也顺查同一标志。

**P2 · 不做：真正 kill 线程**
- Python 侧无法安全杀线程；强杀会留下**写了一半的补丁**、可能来不及 flush 的审计记录，而 `EditTransaction` 与检查点机制都假定「一个 step 是原子的」。
- 代之以 UX 补偿：点暂停后按钮进入**「停止中…」**态（禁用 + 文案变化），若超过 **3 秒**仍未停下，才在原位出现一个**二级动作「强制结束」**（走一个显式标注「可能留下半截输出」的确认）。
- 这一档刻意不碰「结构化补丁是唯一落盘入口」（ADR-004）与「高危强制人审」（ADR-008）两条红线中的任何一条 —— 它只是把清理工作交给用户显式确认。

### 1.4 交互与快捷键

- 快捷键建议 **Esc 走优先级链**：有浮层/抽屉 → 关它；有审批 → 拒绝（现有）；**运行中 → 中断**；都不满足 → 无操作。
  - 现有 Escape 分支清单（改的时候别漏）：`app.js:1791/1813`（终端内，属于终端、不参与本链）、`2343`、`2436`、`3294`、`3647`、`8217`、`8242`、`8480`。
  - 约束：焦点在终端里时不接这条链（终端自己的应用模式要用 Esc）。
- 暂停后 composer 状态文案从「运行中」改为「正在停止…」，直到收到 `run.interrupted`。

### 1.5 改点清单

| 层 | 文件 | 改动 |
|---|---|---|
| HTML | `host/ui/index.html` | `.composer-box` 内 `#btn-send` 后加 `#btn-stop` |
| JS | `host/ui/app.js` | 按钮绑定；`setState()` 里同步两个按钮；Esc 链补「运行中 → 中断」；「停止中」文案态 |
| CSS | `host/ui/styles.css` | `#btn-stop` 常态/运行态两档样式（与 `.btn-primary` 区分） |

| 后端 | `llm/openai_compat.py` | 传输层 `cancel()` 与「被取消 ≠ 网络错误」的异常分类 |

### 1.6 取舍表

## §2 U2 —— 每条对话下面的回退

### 2.1 好消息：后端已经按「轮」建检查点了

| 事实 | 坐标 |
|---|---|
| 每个 `run()` 开一个检查点，结束时提交（`kind="run"`） | `loop/agent.py:826` `begin()` → `:831` `commit()` |
| **restore(cp) 的语义 = 回到那一轮 run 开始之前** | `checkpoint.py:326` docstring |
| 且它是正确的「之后所有轮一起退」：取目标及其**之后所有**检查点的受管文件并集，沿快照链回溯到目标时刻的内容 | `checkpoint.py:337-352` |
| 「回滚本身可撤销」已实现（`redo_id` 反向检查点） | `checkpoint.py:413` `_snapshot_reverse` |
| 恢复前要过 PathGuard、校验 sha256、写回后再验一次，失败整体拒绝 | `checkpoint.py:354-400` |
| 前端已经能在每轮结束后拿到 `checkpointId` | `session.py:3755` → `app.js:4801` `addCheckpointBanner` |
| API 齐了：`GET /api/checkpoints`、`POST /api/checkpoints/{id}/restore`（运行中 409，失败 400） | `server.py:1892-1910` |
| 恢复结果已含 `restored / deleted / unchanged / redoId` | `session.py:2371` |

**结论：这不是一个「要做回滚」的活，是一个「把已有的回滚放到手指够得着的地方」的活。**

### 2.2 缺的三件事

1. 现在的「回滚」横幅是把 CP-ID 塞给 `openCheckpoints()` → 弹出检查点列表 → **用户还要再选一次**。这一步多余。
2. 回退前**看不到要退掉哪些文件**（`RestoreReport` 里有，但列表 API `to_api()` 只给了 `files: string[]`）。
3. 回退后**对话与磁盘会错位**：界面上还写着「已修改 A 文件」，磁盘上却没有 —— 这是这个功能最容易做错的地方。

### 2.3 方案

**（a）按钮挂到那一轮上**
- `run.finished` 带 `checkpointId` 时（无该字段 = 这一轮没动文件 = **不给按钮**，现状一致），把 id 记进 `S.turns = [{ seq, cpId }]`，并在那条 assistant 消息的**底部**渲染一条轻量脚注条：
  `⟲ 撤回这一轮的改动 · 3 个文件`（hover：`退回到这一条提问之前`）。
- 点击 → **一次**轻量确认气泡（显示文件清单），确认即直接 `POST /api/checkpoints/{id}/restore`。不再经过检查点弹窗。
- 检查点弹窗保留 —— 它是「跨轮任意回退」的入口（顶栏 ⟲ 回滚），与本功能并存不冲突。

**（b）回退前能看到「退的是什么」**
- `to_api()` 里把 `files` 从路径数组扩成 `{path, kind}`（`kind`: `mod` / `new` / `del`，取自 `FileEntry.existed` 与当前磁盘对比）—— 或者更简单：给 `GET /api/checkpoints/{id}` 增加详情（含 `restored` 预估）。
- 推荐**前者**：不新增端点，`to_api()` 加一个 `kind` 字段即可，符合 0 依赖/少端点的纪律。

**（c）回退后给「撤销」**
- `session.restore_checkpoint` 已返回 `redoId` → 回退完成后，在对话里插入一条系统消息：
  `已退回到第 N 轮之前：恢复 2 个文件、移除 1 个新建文件。 · [撤销]` → 撤销 = `restore(redoId)`。
- 之后刷新改动面板（已有 `refreshChanges`）。

**（d）不可用时要说清为什么**
- 运行中：按钮 disabled，title「任务执行中，先暂停」。（后端已 409 `BusyError`）
- 超出保留范围：`keep = DEFAULT_KEEP = 10`（`checkpoint.py:46`、`_prune` 会淘汰最旧）。启动时拉一次 `GET /api/checkpoints`，不在列表里的 id → **隐藏按钮**（而不是留个点不动的死按钮），title 解释「只保留最近 10 轮的回滚点」。
- 回退产生的 `redo` 检查点也落在同一个目录里、同样参与裁剪 —— 所以「撤销」按钮也可能因为被裁掉而消失，**与之同一套处理**（列表里没有就隐藏）。

### 2.4 关键设计决策：回退 ≠ 改写历史

回退到某 N 轮之后，有两种处理对话记录的口径：

| 口径 | 做法 | 评价 |
|---|---|---|
| **A. 只回滚磁盘，对话原样** | 文件回到 N 轮前；第 N 轮及之后的 assistant 消息**标记为已废弃**（灰化 + 右上角「已回退」），但保留在对话里 | ✅ **推荐为默认** |
| **B. 连上下文一起截断** | 同时把 `ctx.messages` 截断到 N 轮之前（相当于事实删除历史） | ⚠️ 与「审计/会话历史是事实」的气质打架，且**不可逆** |

选 A 的理由：**对话是本会话发生过什么的记录，它本身也是证据。** 静默把历史删掉，会让人分不清「模型没做过」和「做过但被我退了」。

但必须承认 A 的代价：**上下文错位** —— 继续追问时，模型的上下文里仍留有第 N 轮的「已写入 A」的工具结果，而磁盘已回到旧状态。

缓解办法（建议包含在方案里）：
- 被标「已废弃」的那些消息**仍然参与上下文**，但在回退后插入一条**系统提醒**（作为一轮 tool/notice 注入，或干脆只是一条 UI 提示 + 下一次提问时自动附带的 notice）：
  `注意：第 N 轮之后的改动已被撤回，以下文件内容可能已过期。` —— 让模型自己意识到要重读文件。
- 若用户想要 B，作为**显式的二级动作**提供：「把这一轮之后的对话也一并丢弃」（第二阶段再做，需要 Session 支持上下文截断，且要落一条审计）。

### 2.5 改点清单

| 层 | 文件 | 改动 |
|---|---|---|
| JS | `host/ui/app.js` | `addCheckpointBanner` → 改为给本轮 assistant 消息挂 footer；新增 `revertTurn(seq)`（带一次确认 + 直接 POST）；`S.turns` 记账；回退后按 seq 给后续消息打 `is-reverted`；「撤销」按钮接 `redoId`；启动时拉检查点列表做可用性校验 |
| CSS | `host/ui/styles.css` | `.turn-foot`（脚注条）、`.msg.is-reverted`（灰化）、`.undo-inline` |
| 后端 | `checkpoint.py` `to_api()` | `files` 扩为 `{path, kind}`，让 UI 能显示「改了 / 新建 / 删除」 |
| 后端 | 无新端点 | `POST /api/checkpoints/{id}/restore` 现状够用 |

### 2.6 边界（方案里要说清的）

- 覆盖不到用户自己在编辑器里手改的内容 —— 检查点只在 Agent 写文件 / Git 放弃改动这两处快照。
- `keep=10` 是硬上限：**第 11 轮及更早的回退点会消失**，这不是 bug，是磁盘配额决策（想放宽就调 `keep`，不在本次范围）。
- 远端工作区（ADR-042 / M13）模式下的文件写入走 `tools/remote.py` 的远端补丁链路，是否也经过同一个 `snapshot_before_write` **需要先验证** —— 若远端写不落本机快照，那么远程工作区模式下就不该显示这个按钮（否则按了没效果，比没有更糟）。这一条要在动工前用一次远端写入实测确认。

## §3 U3 —— 远程设备工作面重设计

### 3.1 现状六条问题（含根因）

| # | 问题 | 证据 |
|---|---|---|
| 1 | **它是一个静态 DOM 节点，不在 `S.editors` 里** → `makeTab`（给 ✕ 的唯一地方）从不认识它 → **关不掉** | `index.html:309` `<div class="editor remote-wrap" data-ed="remote">` vs `app.js:1916 openEditor()` |
| 2 | 因此 `updateLayout()` 的 `has-open-tab` 不认它，SOLO/IDE 布局切换也不管它 | `app.js:8135` |
| 3 | 三栏固定比例 `262px / flex / 44%`，塞在宽度本就紧张的编辑器区里，加上右槽聊天面板，**每一栏都不够宽** | `styles.css:1328-1333` |
| 4 | 「新增/编辑连接」表单**常驻** 11 个控件（名称/主机/用户/端口/根/私钥/跳板/策略/两个勾选/备注），把真正要紧的连接列表挤成一条 | `index.html:324-349` |
| 5 | 顶栏堆了 6 类元素（标题 + 数量徽标 + 活动 chip + 「执行中」chip + 刷新），信息层级扁平 | `index.html:311-317` |
| 6 | 「加入工作区」只有「加根目录」一个入口；已经加入的位置没有展示，也没有移出入口（后端已有 `POST /api/remote/roots/{id}/delete`） | `index.html:354` / `server.py:2087-2120` |

> 副作用：因为关不掉，**打开着的远端 SSH 会话始终挂在进程里**（不像 P3 的 `ssh -L` 转发有 `onClose` 钩子回收）。

### 3.2 方案 A：让它成为真正的标签页（解决「只能打开不能关闭」）

把 `switchPanel('remote')`（`app.js:3573`）从 `activateEditor('remote')` 改为：

```js
openEditor('remote', '⧉', `远程设备 · ${display}`, $('#remote-view'),
           { kind: 'remote', closeable: true, onClose: closeRemotePanel });
```

要点：
- `openEditor` 会给节点加 `class="editor"` 并挂 `#editor-host`，因此**要删掉** `index.html` 上那一句 `class="editor remote-wrap"` 和 CSS 里的 `position:absolute; inset:0; display:none` + `.is-active{display:flex}` 特例（`styles.css:1309-1314`）—— 之后它就跟别的文件标签一样由 `.editor.is-active` 统一管。
- `activateEditor()`（`app.js:1846`）补一个 `kind === 'remote'` 分支：主工具条 `#edtoolbar` 让位（与 preview 类同一处理），面板自带的那条 `.remote-bar` 才是它的工具条。
- `closeEditor()` 已有 `onClose` 钩子（P3 加的，本来是给 `ssh -L` 用的）—— 这里复用它做**远端会话回收**：清 `S.remote` 活动连接缓存、撤销远端预览转发、不再维持 SSH 会话。
- 关闭时把 `S.activePanel` 拨回 `explorer`（否则活动栏图标的高亮会停留在 remote）。
- 换来的一项**额外收益**：`updateLayout()` 的 `has-open-tab` 自动生效，SOLO 模式下打开它也会像别的标签一样把编辑器区撑出来。

具体改动：
1. **表单折叠**：`+ 新建连接` 默认折叠；点开后在连接列表下方**行内展开**（或用一个小弹层），不再是常驻 11 个控件。编辑某条连接时用同一份表单填值展开。**这一步单独就能解决「界面很乱」的一大半。**
2. **连接卡片化**：现在是平铺列表 + 一堆诊断文本。改成紧凑卡片：名称 + 目标 + 一行徽标（⬢ 已连/⬡ 未连、只读/可写、可执行），hover 出 ✎ / 🗑。诊断问题（连接失败原因）收进卡片内的**可展开一行**，不要常驻。
3. **文件树占主视觉**：路径做成面包屑（`srv / app / src` 可点），右侧面板改为**可拖宽度**（默认 46%，可拖到 0 = 只留树），并允许全收。
4. **「加入工作区」显式化**：在树下方加一个「已加入工作区」区块，条目形如 `@remote/devbox/app · 已对 Agent 开放 ✕`；✕ = 后端已有的 `POST /api/remote/roots/{id}/delete`。目录右键也补上「加入工作区」（后端 `match_root` 本来就支持子目录，现在 UI 只暴露了根目录）。
5. **上下文条合并**：把标题、活动连接、权限、执行中状态合成一行，右侧只留一个 ⟳ 与 ⋮（⋮ 里放「设为默认连接」「重新检测」等低频动作）。

### 3.4 响应式

- 编辑器区宽度 **< 980px**（笔记本再加 420px 聊天面板，很容易落在这个区间）：连接栏自动折叠 —— 上下文条里出现 `[连接 ▾]` 下拉，点击以抽屉形式覆盖左半屏，选完自动收。**保证任何宽度下树都不被压到无法使用。**
- **< 720px**：单栏，树 / 文件面板二选一（像手机上的邮件客户端），右侧面板以全屏覆盖打开，左上角「返回」。

| 选择 | 理由 / 代价 |
|---|---|
| 做成标签页而不是「侧栏面板」 | 三栏塞进 ~300px 侧栏不可行；标签页还与 welcome/preview 对称，`updateLayout`、`has-open-tab`、SOLO 全部自动生效 |

## §4 落地顺序建议

**第一批（UI 收益 / 改动小）**：U1-P0（composer 暂停键）、U2（回退按钮就地化）。
**第二批（体验真正见效）**：U1-P1（shell 轮询 + LLM cancel），没有它「暂停」在长命令面前仍是句客气话。
**第三批（体量最大）**：U3 —— 先做「变成标签页」（一改即可关闭），再做布局重排，最后做响应式。

每项都要补一层 UI 契约测试（`tests/test_remote_ui.py` 那一类：直接读 `app.js` / `index.html` 原文做断言），并按项目惯例做**反向验证** —— 改坏实现，确认对应的断言真的会变红。

### 验收口径（建议照抄到各自的任务卡里）

- U1：运行时暂停键可点；在跑 `sleep 300` 的命令上点它，≤ 1 秒内返回 `interrupted`（而不是等命令跑完）；中断后保留半截答案、走 `run.interrupted` 收尾，不显示成红色报错；审计里有一条 `agent.run.interrupt_requested`。
- U2：每一条有改动的 assistant 消息下方出现回退条；点一次确认即完成；回退后文件与 N 轮前逐字节一致（对齐 `RestoreReport` 的 sha256 自检）；「撤销」能把文件原样恢复；超过 10 轮的老消息不显示该按钮。
- U3：面板可被 ✕ 关闭；关闭后 `.act[data-panel="remote"]` 回到未选中、SSH 会话被回收；再点图标能重新打开；宽度压到 900px 时连接栏自动折叠且树仍可用。
