# M15：通用多智能体协作执行

## 已实现的第一版

使用 `VIBE_COLLABORATION=1` 启用。启用后底部输入框上方出现「单智能体 / 多智能体」切换；左侧「协作」页签只读展示历史记录。默认关闭；关闭时不创建协作数据库，切换控件也不渲染，发送行为与改造前一致。

1. 主对话框输入总目标，切到「多智能体」发送；系统先调用协调模型生成分工计划（也可通过 API 提交自定义计划）。
2. 计划以卡片出现在对话流：审查任务（角色、依赖、资源、产出、验收），可编辑 JSON 保存修订；点「确认执行」才开始，点「取消」不执行。规划失败时可重试或手动填写任务 JSON。
3. 执行中卡片显示各任务进度，可停止；全部任务通过独立验收后出现「审查并交付」。左侧「协作」页签只读，用于回看历史项目、验收记录与文本成果。
4. 独立任务默认两个并行；依赖任务等待前序验收通过；同名资源互斥。
5. 每个任务有独立 attempt 目录、角色、目标、交付物、验收条件、时间和调用预算。
6. Agent 写入声明的文本交付物，仍经现有审批；不能修改原工作区。
7. 独立只读验收 Agent 检查文件和验收条件。缺失或超过 20 MB 的成果由调度器直接拒绝。
8. 整场通过后审批交付到 `collaboration-deliveries/<项目>-v<版本>/`。
9. 停止后可重试：保留已成功任务，仅执行失败或被阻塞的任务。重启留下的执行态标为 interrupted。
10. 补充要求会停止当前执行，要求保存新版本计划后再执行，避免旧成果沿用新约束。

## 数据与 API

- SQLite：`.vibe/collaborations/projects.db`，保存项目、任务、版本、消息与成果清单。
- 成果：`.vibe/collaborations/<项目>/v<版本>/<任务>/attempt-<次数>/`。
- 前序交付物复制至后续任务的 `inputs/<任务>/`，复制前校验 SHA256。
- GET/POST `/api/collaborations`：查询项目 / 创建草案（goal、requestId；可选 tasks，不填则调用协调模型生成）。
- GET `/api/collaborations/<id>`：项目详情。
- POST `/api/collaborations/<id>/start`：执行或重试。
- POST `/api/collaborations/<id>/stop`：请求停止。
- POST `/api/collaborations/<id>/revise`：tasks + revision，乐观锁修订；必须先停止。
- POST `/api/collaborations/<id>/message`：text，补充要求并要求修订。
- POST `/api/collaborations/<id>/artifact`：taskId + name，读取已验收文本成果（预览最多 200 KB）。
- POST `/api/collaborations/<id>/deliver`：审批后创建新交付目录，禁止覆盖。

所有 API 沿用宿主 token 和来源检查。审计仅记录项目/任务 ID 和状态，不记正文。

## 边界与后续阶段

通用调度器可注入 runner，首个内置适配器仅支持源文件读取和隔离文本写入。代码可以生成和审查，但尚不能实际执行测试；CAD、图片生成、终端、MCP、远程和桌面应用需要独立适配器。资源锁当前作用域是一场协作，不能替代操作系统或跨会话锁。

首版每个会话只执行一个项目；不支持多进程同时拥有同一项目。主会话和外部编辑器不受资源锁约束；读取源文件时记录哈希，并在本次验收结束核对，发生变化则失败。尚未实现整个项目的启动输入快照与跨任务源版本一致性。

执行者与验收者共享当前模型端点，但上下文独立。每任务最多 28 次模型请求，执行者最多 12 次迭代、验收者最多 8 次；每任务 10–1800 秒，默认 300 秒。标准客户端限制请求超时，取消在模型调用/Agent 迭代边界生效，自定义阻塞客户端必须实现超时。没有启动脱离控制的工具线程。

当前角色由计划指定，尚未绑定 M14 档案；计划修订由用户发起，尚未实现结构化变更请求、问题分派及自主重新规划。集成/整体验收通过显式依赖任务表达；系统不强制每个手工计划都包含独立的最终集成节点。通用代码执行与外部资源能力接入后，再完善自动测试和不同成果类型的验证器。

交付审批目前展示成果清单与哈希，用户可以先从面板查看文本；尚未提供二进制预览或对原仓库逐文件合并。交付采用同文件系统临时目录 rename，不宣称跨目录多文件事务。
