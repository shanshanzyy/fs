# VibeAgent 便携版使用指南（v0.1.0 / Windows x64）

面向「把 zip 发给同事，对方自己跑起来」的场景。读完这一份就够了：
装、配模型、会用、出问题怎么办。

- 下载地址：<https://github.com/shanshanzyy/fs/releases/tag/v0.1.0>
- 资产名：`VibeAgent-0.1.0-win-x64-portable.zip`
- 体积：约 174 MB（解压后约 391 MB）
- sha256：`93028762e107140d68286be697c09a28fa7598e2d15945cce76b7ba741a1743c`

> 便携版与安装版**功能完全一致**，区别只有一个：便携版不写注册表、不建快捷方式，
> 删目录即卸载。本版次未提供 NSIS 安装包。

---

## 1. 它是什么

本地化 AI 编码智能体：用自然语言描述需求，Agent 自己读代码、定位问题、生成**结构化补丁**，
等你审批后落盘、跑测试。执行面全在本机，代码不出内网；治理面（可选）只做策略与审计。

软件**不含模型权重，也不含任何 API Key** —— 模型能力来自你自己连的那个服务。

## 2. 包内结构

解压后得到一个目录：

```
VibeAgent-0.1.0-win-x64\
├─ VibeAgent.exe                     ← 双击这个
├─ resources\
│  ├─ app.asar                       桌面壳代码（main / backend / preload / update）
│  ├─ backend\
│  │  ├─ vibe-agent-core.exe         内嵌后端（Python 运行时已打包，无需另装）
│  │  └─ version.json                内核版本
│  └─ elevate.exe
├─ locales\  *.pak  *.dll  *.bin     Electron / Chromium 运行时
└─ LICENSE.electron.txt  LICENSES.chromium.html
```

**别只拷 `VibeAgent.exe`** —— 旁边那些 `*.dll`、`*.pak`、`resources\` 都是必需的。

## 3. 运行要求

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10 / 11，x64 |
| 运行时 | 无。不需要 Python、Node、.NET、VC++ 运行库 |
| 权限 | 普通用户即可，**不需要管理员** |
| 磁盘 | ≥ 1.5 GB 空闲（程序 391 MB + 会话/检查点/临时解压） |
| 内存 | 建议 ≥ 8 GB（Electron 壳 + 后端 + 模型客户端） |
| 网络 | 能访问你的模型服务地址（跨机器时确认防火墙放通对应端口） |

**唯一的硬前提：一个 OpenAI 兼容模型服务。**
满足 `POST /v1/chat/completions`、支持流式（SSE）即可，例如：

- 本机 Ollama（`http://127.0.0.1:11434/v1`）
- vLLM / SGLang / LM Studio / llama.cpp server
- 公司内网的推理服务（如 `http://10.0.1.50:8002/v1`）

## 5. 解压与放置位置

解压到**任意可写目录**，例如：

- 推荐：`D:\Tools\VibeAgent\`、`C:\Users\<你>\Apps\VibeAgent\`
- 可用：`%LOCALAPPDATA%\VibeAgentPortable\`

**不建议**放在这些位置（会被系统策略或同步机制拦）：

- `C:\Program Files\`（只读，且触发 UAC）
- 某些同步盘目录（OneDrive 占位文件、企业网盘）
- 只读共享、网络盘
- 路径过深或含特殊字符的目录

> 实测：程序从受限路径（如某些工作区/沙箱目录）双击会被系统直接拒绝启动，
> 表现是「没有任何窗口」或「Start-Process: 操作被用户取消」。换到上述推荐目录即可。

## 6. 首次启动

双击 `VibeAgent.exe`，等待 3–10 秒（首次启动要解压内嵌后端到临时目录）。

正常现象：

- 出现标题为 **Vibe Coding Agent** 的窗口
- 顶部有「工作区」「模型」「治理面」等按钮，左侧有图标栏
- 中间是欢迎页

可能遇到的拦截：

| 提示 | 处理 |
|---|---|
| 「Windows 已保护你的电脑」（SmartScreen） | 点「更多信息 → 仍要运行」。内部未签名构建，属正常 |
| 杀毒软件报「未知程序」 | 加白名单/信任该目录（后端是 PyInstaller 打包的自研代码，无网络回连） |
| 双击后没反应 | 换到 §5 的推荐目录；或先看 §13 的排查步骤 |

## 7. 配置模型（关键一步）

点顶部 **模型** 徽标（或右上「设置」）→「模型设置」：

| 字段 | 填写说明 | 示例 |
|---|---|---|
| 接入地址 | OpenAI 兼容地址，**通常以 `/v1` 结尾** | `http://10.0.1.50:8002/v1` |
| 模型 | 服务端实际支持的模型名 | `deepseek-v4-flash` |
| API Key | 内网/本地服务可随便填（如 `sk-local`），云端服务填真 Key | `sk-local` |
| 光标前/后上下文窗口 | 内联补全的上下文截取长度（字符），0 = 不截断 | 默认即可 |

操作要点：

1. 先点 **刷新列表** —— 能从接入地址拉到模型就说明地址可达，下拉里直接选模型。
2. 点 **保存**：**立即生效，当前对话不丢**。
3. 保存后看顶部模型徽标是否变成你选的模型。
4. 跑一次「列出这个项目的目录结构」，有回答就说明整条链路通了。

三种常见服务怎么写：

```text
# 本机 Ollama
接入地址 http://127.0.0.1:11434/v1     模型 qwen2.5-coder:7b      API Key 留空或任意

# LM Studio / vLLM（本机）
接入地址 http://127.0.0.1:8000/v1      模型 <服务里加载的模型名>

# 公司内网推理服务
接入地址 http://10.0.1.50:8002/v1      模型 deepseek-v4-flash     API Key <按内网要求>
```

> 字段优先级：**环境变量 > `~/.vibe/settings.json` > 桌面壳 `config.json` > 内核默认**。
> 被环境变量锁定的字段在界面上会置灰 —— 那是运维统一配置，属地化管理。

## 9. 基本工作流

1. **选工作区**：点顶栏「工作区」→ 选你的项目目录（**建议是 Git 仓库**，便于看改动与回滚）。
2. **新会话**：点「＋ 新会话」。
3. **描述需求**：例如「修复 `src/utils.py` 里 average 遇到空列表崩溃的问题」。
   可以 `@文件`、`@符号`、`@文件夹` 引用上下文。
4. **看它干活**：读文件 → 出计划 → 生成补丁。
5. **审批**：出现审批浮层时看 diff，`批准` / `拒绝`；高危操作（写盘、跑命令、删改）
   **一律要你点**，且不能通过配置静默放行。
6. **看结果**：「改动」面板核对真实 diff。
7. **不满意**：点「⟲ 回滚」回到某轮改动之前（回滚本身也可撤销，会逐条列出恢复/删除/跳过）。
8. **会话一直在**：关闭客户端再打开，历史会话仍在「历史会话」面板里。

## 10. 进阶功能（按需）

| 功能 | 怎么用 | 默认 |
|---|---|---|
| 内联补全 | 编辑器里直接敲，等灰字候选，`Tab` 采纳 | 开（需模型支持） |
| 行内改写 | 选中代码 → 让模型改 | 开 |
| LSP 诊断/跳转/重命名 | 自动，取决于语言服务是否可用 | 开 |
| 预览 | 内置页面/本地静态服务预览 | 开（外部预览需开 `VIBE_PREVIEW_REMOTE`） |
| MCP | 侧栏 MCP 面板，写 `<工作区>\.vibe\mcp.json` | 需 `VIBE_MCP=1` |
| 终端 | 内置终端面板，多标签、可拖拽高度 | 开 |
| 远程设备 | 侧栏「远程设备」，SSH 连接远端做文件工作面 | 需 `VIBE_REMOTE=1` |
| 定时任务 | 侧栏「定时任务」，cron / `@every` / `@at` | 需 `VIBE_SCHEDULER=1` |
| 后台/并行任务 | 侧栏「后台任务」 | 需 `VIBE_ASYNC_AGENT=1` |
| Skill 工作流 | 命令面板里 `/skills`、`/skill` | 开 |
| 调试器 / 扩展 | 开发向能力 | 需 `VIBE_DEBUG=1` / `VIBE_EXTENSIONS=1` |
| 联网检索 | `web_search` / `web_fetch`，恒走审批 | 需显式开启 |

**便携版怎么设环境变量**（重启客户端后生效）：

```powershell
# 方式一：只对这一次启动有效
$env:VIBE_MCP=1; & 'D:\Tools\VibeAgent\VibeAgent-0.1.0-win-x64\VibeAgent.exe'

# 方式二：写进当前用户环境变量（长期生效，重开客户端即可）
[Environment]::SetEnvironmentVariable('VIBE_MCP','1','User')
```

## 11. 可选的治理面（多人协作时才需要）

治理面是独立进程（内网一台常驻机器），负责策略、配额、审计、发布；**不托管你的代码**。

接入方式：

1. 让运维给你治理面地址（如 `http://10.0.1.9:8787`）。
2. 客户端顶部点「治理面」→ 填地址 → 登录（或邀请码注册）。
3. 登录后策略下发，界面顶部出现治理状态徽标。

**边界（实测口径）**：

- 治理面策略**禁云 / 过期 / 降级 / 未登录**时，模型请求走本机客户端 ——
  此时「模型设置」与 MCP 配置**照常可改**（本机文件就是权威）。
- 只有策略允许上云、模型请求真的经云端网关发出时，才会锁模型配置（界面提示原因）。
- 不配治理面就是纯本地模式，全部功能可用。

## 12. 数据在哪 / 备份 / 卸载

| 位置 | 内容 |
|---|---|
| `%APPDATA%\VibeAgent\config.json` | 桌面壳配置：解释器路径、治理面地址、窗口状态 |
| `~/.vibe\settings.json` | 「模型设置」保存的配置 |
| `~/.vibe\` | 凭据、策略缓存、记忆库（若启用） |
| `<工作区>\.vibe\` | 会话库、检查点、审计哈希链、`mcp.json`、定时任务库 |
| `%TEMP%\_MEI*` | 后端运行时临时解压目录（正常退出会清理） |

- **备份**：拷 `<工作区>\.vibe\` + `%APPDATA%\VibeAgent\`；模型配置在 `~/.vibe\settings.json`。
- **迁移到新电脑**：拷整个程序目录 + `%APPDATA%\VibeAgent\` + `~/.vibe\settings.json` 即可。
- **卸载**：直接删程序目录；再按需删 `%APPDATA%\VibeAgent\` 与 `~/.vibe\`。
  不写注册表、不建快捷方式、**不留后台服务**。

## 13. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 双击没反应 / 提示「操作被用户取消」 | 目录受限（§5）。换个可写目录再试 |
| 启动后白屏 / 一直转圈 | 后端没起来。在终端手动跑：`.\resources\backend\vibe-agent-core.exe --workspace D:\你的项目 --no-open --print-url`，看报错 |
| 提示 `Could not create temporary directory!` | 临时目录不可写（杀软/策略）。把 `TEMP`/`TMP` 指到可写目录再启动，或清理 `%TEMP%\_MEI*` |
| 模型列表刷新失败 | 地址不可达或不是 OpenAI 兼容路径；确认以 `/v1` 结尾、能 `curl` 通 |
| 对话报 401 / 403 | API Key 不对或该服务要求鉴权头；改 Key 后保存即生效 |
| 对话报 429 | 服务端限流（TPM/RPM）；降低并发/换模型/等窗口恢复 |
| 一直「停止中」 | 旧版本行为；本版已支持流式阶段立即中断。仍出现就更新内核 |
| 终端里中文打不出来 | 需窗口聚焦且输入法可用；本版已支持输入法组合事件 |
| 终端/内嵌网页白屏 | 桌面壳用 `webview` 渲染外部页面；若目标站点仍拒绝，换内置预览 |
| 想开第二个客户端 | 单实例：第二次启动会聚焦已有窗口 |
| 审批浮层没出现就写盘了 | 不可能：写盘/命令/高危操作恒需审批（ADR-004/015） |
| 想彻底重置 | 关客户端 → 删 `%APPDATA%\VibeAgent\` 与 `<工作区>\.vibe\` → 重启 |

## 14. 安全边界（请知悉）

1. **代码不出本机**：文件读写、命令执行、索引与向量化都在客户端；治理面只存元数据与审计。
2. **编辑必须走结构化补丁**：不允许整文件重写（唯一受控例外需显式声明 `overwrite`）。
3. **高危操作强制人工审批**：不能通过配置或环境变量关闭，只有会话内显式放行才可通过。
4. **不信任输入**：读到的代码注释、Issue 内容都按不可信文本处理（防 Prompt Injection）。
5. **本包未签名**：分发时请走可信渠道，并核对 §4 的 sha256。
